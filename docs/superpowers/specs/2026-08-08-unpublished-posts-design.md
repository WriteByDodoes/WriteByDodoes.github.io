# 비공개 글 처리 설계

## 목표

글 Markdown 파일은 GitHub 저장소에 보존하면서 `published: false`로 표시한 글을 로컬 및 배포 블로그에서 완전히 제외한다. 별도의 초안 관리 화면이나 환경별 동작은 추가하지 않는다.

## 작성 인터페이스

글의 front matter에 다음 값을 선택적으로 사용한다.

```yaml
published: false
```

- `published`가 없거나 `true`이면 기존과 동일하게 게시한다.
- `published`가 정확히 불리언 `false`이면 비공개로 처리한다.
- 문자열 `"false"`는 지원하지 않는다. YAML 불리언을 사용해야 한다.

## 빌드 동작

`src/writing/writing.11tydata.js`의 계산된 permalink가 비공개 글에 대해 `false`를 반환하도록 한다. 따라서 해당 글의 HTML 출력 파일과 직접 접근 URL이 생성되지 않는다.

`eleventy.config.js`의 글 컬렉션 생성 단계에서도 `published: false`인 항목을 제외한다. 홈, 전체 글, 카테고리, 관련 글 추천은 모두 이 필터링된 컬렉션을 사용하므로 비공개 글이 노출되거나 개수에 포함되지 않는다.

사이트맵은 출력 URL이 있는 페이지만 취급하므로 비공개 글을 포함하지 않는다. 기존의 공개 글 URL, 정렬, 페이지네이션 및 카테고리 동작은 유지한다.

## 오류 및 경계 조건

- `published` 누락은 공개로 간주해 기존 글의 동작을 보존한다.
- `published: true`도 공개로 처리한다.
- 비공개 글의 카테고리와 날짜가 유효하더라도 컬렉션과 출력에서 제외한다.
- GitHub 저장소가 공개되어 있다면 Markdown 원본 자체는 계속 공개된다. 이 기능은 웹사이트 게시만 막으며 비밀 보관 기능은 아니다.
- 이전 빌드에 생성된 HTML이 남지 않도록 기존 프로덕션 빌드의 `clean` 단계를 유지한다.

## 문서화

README의 글 작성 안내에 `published` 필드와 비공개 처리 범위를 설명한다. 사용자가 숨기려는 기존 글에는 직접 `published: false`를 추가할 수 있다. 이번 변경에서는 어떤 기존 글도 임의로 숨기지 않는다.

## 검증

- 공개 글과 비공개 글을 대표하는 테스트 데이터로 컬렉션 필터와 permalink 동작을 검증한다.
- 프로덕션 빌드가 성공하는지 확인한다.
- 비공개 테스트 글의 출력 HTML이 없고 공개 글 및 아카이브 출력은 유지되는지 확인한다.
- 테스트를 위해 만든 임시 콘텐츠가 최종 변경에 남지 않는지 확인한다.
